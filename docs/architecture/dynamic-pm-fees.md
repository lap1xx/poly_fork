# Динамическая комиссия Polymarket

## Источник и границы модели

Сканер получает параметры taker fee для конкретного рынка из CLOB API `GET /clob-markets/{condition_id}`. В текущем ответе параметры кривой находятся в `fd`: `r` — ставка, `e` — показатель степени, `to` — признак комиссии только для taker. Общий модуль `pm_fees.py` нормализует их в `rate` и `exponent`; данные кэшируются на 300 секунд. Для совместимости также поддерживается прежняя форма `feeSchedule`. Если параметры отсутствуют, некорректны или недоступны, кандидат не рассчитывается как достоверная возможность: фиксированная ставка 4% не подставляется.

Для непрерывной оценки комиссии на уровне цены `p` применяется опубликованная кривая:

```text
fee_per_share = rate * (p * (1 - p)) ** exponent
```

Для объёма `shares` оценка комиссии равна `shares * fee_per_share`. При расчёте глубины стакана комиссионная стоимость каждой доли прибавляется к цене уровня. Это оценка для read-only мониторинга, не симуляция всех правил исполнения.

## Неопределённость исполнения

Фактическая комиссия округляется по правилам торговой системы; возможны минимумы и различия, относящиеся к конкретному рынку или исполнению. Поэтому непрерывный расчёт может отличаться от фактического списания на малых объёмах и около границ округления. Интерфейс должен обозначать результат как оценочный и не обещать исполнение или прибыль. Автоматическое размещение заявок в проекте не включается.
