# 1win: read-only источник коэффициентов

Дата проверки: 2026-11-19. Интеграция предназначена для личного мониторинга и чтения котировок. Она не размещает ставки, не вызывает betslip/account/wallet API и открывает только обычную страницу события.

## Источники и подтверждённые маршруты

Проверка выполнена на предоставленных пользователем страницах события:

- https://f1w-7707.com/betting/match/esport/heroic-vs-imperial-42554132
- https://f1w-7707.com/betting/match/esport/downpour-vs-vawpirchik-43439172

В загруженном frontend bundle страницы (ресурс `/assets/betting-*.js` на том же домене) подтверждены названия обработчиков и подписок `match-odds`, `match-odds-snapshot` и `subscribe-match-odds`. Официальный путь live-котировок — Engine.IO/Socket.IO feed `push-server-v2`, а не `sportfeed-feature-ws`. Последний используется frontend для отдельного key-value feature feed; в нём не обрабатываются match odds.

Каталог событий читается read-only POST-запросами к `https://api-gateway.top-parser.com/matches/get-many` по полю `sportId`. Проверены виды спорта CS2 (142), DOTA2 (47), LOL (37), VALORANT (99) и теннис (33). В ответе каталог содержит `id`, `slug`, `sportType`, команды с именами и slug, а также `sportId`/`sport.slug`.

Котировки читаются с `wss://api-gateway.top-parser.com/push-server-v2/` через Engine.IO v4. Frontend подписывает матч на `subscribe-match-info` и на две версии `subscribe-match-odds`: базовые группы (`isBaseOddsGroups=true`) и полный набор групп (`false`). Используемые события — `match-odds-snapshot` для начального снимка и `match-odds` для обновлений. Типичная структура содержит `matchId`, `isBaseOddsGroups`, `oddsGroups[]` и `oddsList[]`; цена находится в `cf`, исход — в полях имени/ID, доступность — в `status`.

## Реализация и защита от ложного сопоставления

Адаптер хранит свежий каталог и обновления feed; после reconnect старые котировки очищаются до получения новых snapshot. Успешный refresh заменяет каталог соответствующего вида спорта и удаляет исчезнувшие события; при ошибке отдельного sport запроса его кэш временно сохраняется. Из snapshot полного набора удаляются исчезнувшие группы. Заблокированные/удалённые исходы, нечисловые цены, цена `<= 1`, отсутствие одной из команд или неоднозначные группы не используются. Каждая сторона должна быть получена не более 30 секунд назад по локальному времени приёма; устаревшие открытые котировки исключаются.

Поддержаны рынки победителя матча и победителя карты с номером карты. Названия команд сопоставляются в прямом и обратном порядке; недостаточный match score приводит к отказу от bind. Если два события имеют score выше порога и разница меньше 0.08, bind отклоняется как неоднозначный. Группа odds также должна однозначно соответствовать рынку и номеру карты, а для двух сторон требуется ровно по одной открытой цене. Неподдерживаемые тоталы, handicap/spread и специальные рынки не угадываются. Router сохраняет BetBoom binding как резерв и использует его, если 1win feed не готов или не возвращает две свежие пригодные цены.

Страница события строится в обычном формате `/betting/match/{sportType}/{slug}-{matchId}`. Например, каталог для `downpour-vs-vawpirchik` и ID `43445591` дал ожидаемый URL `https://f1w-7707.com/betting/match/esport/downpour-vs-vawpirchik-43445591`. Ссылка не содержит суммы, купона или payload для ставки.

## Проверки

- Read-only smoke test установил WebSocket-соединение и получил каталог примерно из 281 события на момент проверки.
- Полный путь REST catalog → odds snapshot → bind → live odds был повторно проверен на событии `Vawpirchik — -kevinG`: адаптер вернул цены 4.46 и 1.17 с возрастом около 2.9 секунды и обычную страницу события `.../vawpirchik-vs-keving-43445927`. Это временные рыночные значения, а не гарантированные текущие котировки.
- Offline-тесты покрывают схему подписки, отсутствие bet placement, карту/победителя, blocked/deleted odds, неоднозначные группы, freshness и обычную event-page ссылку.

## Конфигурация

Параметры API base, origin, языка, публичного partner identifier и максимального возраста котировки могут быть переопределены переменными `ONEWIN_API_BASE`, `ONEWIN_ORIGIN`, `ONEWIN_LANGUAGE`, `ONEWIN_PARTNER_ID` и `ONEWIN_MAX_ODDS_AGE_SECONDS` (1–600 секунд; default 30). Адаптер не добавляет заголовок подмены региона. При невозможности сопоставить событие или рынок router оставляет BetBoom резервным источником; флаг `--no-bb` отключает только этот резерв, но не 1win.
